# Technology and automation

## Mandate

Identify technologies that improve specific outcomes under realistic operating conditions and economics.

## Working role

Approach the assigned work as a automation engineer and technology adoption analyst. Use that expertise to investigate, quantify, and challenge assumptions. This charter describes a research perspective; it does not confer professional credentials or authorize external actions.

## First questions

- Build task-level cases for AI assistance, robotics, construction tools, farming, delivery, and compute infrastructure.
- Separate available deployed capability, vendor demonstrations, and speculative future performance.
- Include integration, supervision, cybersecurity, energy, maintenance, replacement, uptime, and human fallback costs.
- Examine ownership, licensing, data stewardship, and whether residents can access useful innovations at lower cost; do not assume hosting infrastructure conveys those rights.

## First useful deliverable

A capability evidence matrix and adoption cases with readiness, lifecycle costs, dependencies, and delayed/failed-deployment alternatives.

Relevant agenda questions: Q-010; Q-011. This is a proposed deliverable, not an active assignment. Select a bounded scope with the operator before beginning a new investigation.

## Evidence to seek

Observed deployments, technical documentation, independent evaluations, documented vendor terms, and comparable operating records.

Use the [shared research method](../../research/METHOD.md), [source catalog](../../research/SOURCE-CATALOG.md), and [assumption register](../../research/ASSUMPTIONS.md). A source category is not a claim that the evidence has been collected.

## Interfaces

Enterprise, food, health, mobility, and construction define actual tasks; energy/water define loads; economics compares total costs; risk tests failures.

For the proposed model: Provide capability boundaries, readiness evidence, adoption timing ranges, effective labor requirements, resource demand, cost, and fallback performance.

## Challenge the preferred idea

Do not use an unproven humanoid, medical AI, autonomous fleet, or cheap compute assumption as the sole support for essential services.

## Record and hand off

Place completed briefs beside this README using a descriptive filename and a date when useful. Start from the [research brief template](../../templates/RESEARCH-BRIEF.md). Link significant results into [findings](../../research/FINDINGS.md), record changes to shared assumptions, and update the [work log](../../coordination/WORK-LOG.md). End with the unresolved question that most changes the recommendation.
