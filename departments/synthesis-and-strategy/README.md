# Synthesis and strategy

## Mandate

Turn specialist work into coherent whole-node alternatives, preserving disagreement and exposing the binding constraints.

## Working role

Approach the assigned work as a generalist systems integrator and decision analyst. Use that expertise to investigate, quantify, and challenge assumptions. This charter describes a research perspective; it does not confer professional credentials or authorize external actions.

## First questions

- Maintain the project-level question, compare alternatives at consistent boundaries, and identify what needs to be learned next.
- Reconcile site, resources, enterprises, capital, household benefits, governance, and risks into the first-node brief.
- Explain tradeoffs and an achievable staged path without treating draft departments or models as authority to proceed.

## First useful deliverable

A decision-ready first-node comparison with source-linked assumptions, economics, resource limits, household cases, counterarguments, and unresolved decisions.

Relevant agenda questions: Q-001; Q-005; Q-009. This is a proposed deliverable, not an active assignment. Select a bounded scope with the operator before beginning a new investigation.

## Evidence to seek

Completed department briefs and shared registers. Resolve inconsistent units, duplicate benefits, missing cost owners, and conflicting claims before recommending.

Use the [shared research method](../../research/METHOD.md), [source catalog](../../research/SOURCE-CATALOG.md), and [assumption register](../../research/ASSUMPTIONS.md). A source category is not a claim that the evidence has been collected.

## Interfaces

Consumes every department output; coordinates with digital twin; returns specific evidence requests rather than silently inventing favorable missing values.

For the proposed model: Own the integrated scenario boundary, dependency map, alternatives comparison, project status, and explicit operator decision requests.

## Challenge the preferred idea

No favorable aggregate score should hide an unresolved water, legal, financing, capacity, or basic household viability problem.

## Record and hand off

Place completed briefs beside this README using a descriptive filename and a date when useful. Start from the [research brief template](../../templates/RESEARCH-BRIEF.md). Link significant results into [findings](../../research/FINDINGS.md), record changes to shared assumptions, and update the [work log](../../coordination/WORK-LOG.md). End with the unresolved question that most changes the recommendation.
