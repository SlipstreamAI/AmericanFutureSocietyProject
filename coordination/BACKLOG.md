# Proposed bounded backlog

These tasks are candidates for operator selection, not standing instructions or a schedule. Task numbers below are backlog identifiers, not claims of active ownership.

| ID | Proposed task | Prerequisites | Useful completion evidence |
| --- | --- | --- | --- |
| B-001 | Reconcile completed outputs from the other ChatGPT conversation | Outputs made available | Provenance, overlap comparison, retained/rejected material, updated assumptions |
| B-002 | Audit the existing site and research kit | Source access and bounded audit scope | Actual file inventory, model/input map, checks reproduced, gap list; no unverified claims inherited |
| B-003 | Define household baselines and desired benefit measures | Operator priority cohorts or explicit proposed cohorts | Complete budgets for renter/owner, remote worker/trades, older/caregiver and seasonal cases; assumptions and alternatives |
| B-004 | Compare minimum viable node alternatives | Vision plus B-003 | Parcel cluster versus town-adjacent versus larger node, with cost/resource/revenue dependencies |
| B-005 | Conduct a regional site screen | Explicit geographic scope and screening criteria | Source-linked critical constraints, unknowns, exclusion reasons, and a small candidate set |
| B-006 | Build enterprise pre-feasibility cases | B-004 context and defined customer segments | Demand evidence, full unit economics, capital, staffing, outside sales, and cash rights |
| B-007 | Compare ownership and institutional alternatives | Defined benefit goals and candidate jurisdictions | Rights, cash waterfalls, funding/exit issues, professional-review questions |
| B-008 | Specify the first executable scenario model | B-002 plus usable evidence from B-003/B-004 | Scoped model design, input provenance, interfaces, tests, validation and uncertainty plan |
| B-009 | Resolve license and contribution terms | Operator review | Explicit license decision for relevant material and reviewed contribution policy |

The exact order can change. Choose the next task by the uncertainty it resolves and the decisions it enables. Do not start B-005 simply because a region was mentioned in the brainstorm, or B-008 because an attractive frontend already exists.
